# FinTrace — Personal Finance Tracker
### Project Plan

---

## 1. Overview

A single-user personal finance tracker that pulls bank transaction data from **Setu AA (Account Aggregator)**, stores and enriches it locally, lets you tag transactions manually, and renders tag-based analytics with outlier flagging.

**Core loop:**
```
Setu AA API → Express server → SQLite (Drizzle ORM) → React frontend (charts + tagging UI)
```

## 4. Setu AA Integration

Setu uses the **Account Aggregator (AA) framework** — a 3-step consent-based flow before any data can be fetched.

### 4.1 Setup (one-time)
1. Create account on [bridge.setu.co](https://bridge.setu.co)
2. Create an FIU (Financial Information User) app
3. Configure your webhook URL (e.g., `http://localhost:4000/webhook/setu`)
4. Add Request Signing public key
5. Get `clientId`, `secret`, and `baseURL` (sandbox: `https://dg-sandbox.setu.co`)

### 4.2 Data Flow (per fetch session)

```
Step 1: POST /consent          → creates consent request, get redirect URL
Step 2: User approves consent  → Setu notifies webhook with consentId
Step 3: POST /sessions         → create data session with consentId
Step 4: Webhook fires          → session status = COMPLETED
Step 5: GET /sessions/{id}     → fetch decrypted FI data (JSON format)
Step 6: Transform + persist    → store normalized transactions in SQLite
```

### 4.3 Transaction Fields from Setu (DEPOSIT FI type)

```typescript
// Raw from Setu
{
  txnId: string;           // "M3258741"
  amount: string;          // "1239"
  type: "DEBIT" | "CREDIT";
  mode: "UPI" | "NEFT" | "IMPS" | "CASH" | "CHEQUE" | ...;
  narration: string;       // "UPI/935314560764/getsimpl/simpl@axisbank/Axis Bank"
  transactionTimestamp: string; // ISO 8601
  currentBalance: string;
  reference: string;
  valueDate: string;
}
```

### 4.4 Normalized Transaction Object (your app's schema)

```typescript
interface Transaction {
  id: string;              // UUID (generated by you, not Setu's txnId)
  setuTxnId: string;       // original txnId from Setu
  amount: number;
  type: "DEBIT" | "CREDIT";
  mode: string;            // UPI, NEFT, etc.
  narration: string;       // raw narration string
  sender: string | null;   // parsed from narration
  receiver: string | null; // parsed from narration
  balance: number;
  timestamp: string;       // ISO 8601
  valueDate: string;
  tags: string[];          // default: []  → "unknown" state = empty array
  isOutlier: boolean;      // default: false
  accountId: string;       // linked bank account ref
  createdAt: string;
}
```

> **Note on sender/receiver:** Setu doesn't explicitly provide these as structured fields. They're embedded in the `narration` string (e.g. `UPI/{refNo}/{receiver_vpa}/{sender_vpa}/Bank`). You'll need a parser to extract them heuristically by mode (UPI, NEFT, etc.).

## 5. Database Schema (Drizzle + SQLite)

```typescript
// schema.ts

export const transactions = sqliteTable('transactions', {
  id:          text('id').primaryKey(),
  setuTxnId:   text('setu_txn_id').unique().notNull(),
  amount:      real('amount').notNull(),
  type:        text('type', { enum: ['DEBIT', 'CREDIT'] }).notNull(),
  mode:        text('mode').notNull(),
  narration:   text('narration').notNull(),
  sender:      text('sender'),
  receiver:    text('receiver'),
  balance:     real('balance').notNull(),
  timestamp:   text('timestamp').notNull(),
  valueDate:   text('value_date').notNull(),
  tags:        text('tags', { mode: 'json' }).$type<string[]>().notNull().default([]),
  isOutlier:   integer('is_outlier', { mode: 'boolean' }).notNull().default(false),
  accountId:   text('account_id').notNull(),
  createdAt:   text('created_at').notNull(),
});

export const tags = sqliteTable('tags', {
  id:    text('id').primaryKey(),
  name:  text('name').unique().notNull(),
  color: text('color').notNull().default('#6366f1'),
});

export const accounts = sqliteTable('accounts', {
  id:                text('id').primaryKey(),
  maskedAccNumber:   text('masked_acc_number').notNull(),
  fipId:             text('fip_id').notNull(),
  linkRefNumber:     text('link_ref_number').notNull(),
  lastFetchedAt:     text('last_fetched_at'),
});
```

|---|---|---|

| Method | Route | Description |
|---|---|---|

## 8. Analytics Logic

All analytics queries **exclude rows where `isOutlier = true`**.

### Tag Spending
```sql
SELECT json_each.value AS tag, SUM(amount) AS total
FROM transactions, json_each(transactions.tags)
WHERE type = 'DEBIT' AND is_outlier = 0
GROUP BY tag
```

### Monthly Summary
```sql
SELECT strftime('%Y-%m', timestamp) AS month,
       SUM(CASE WHEN type='DEBIT' THEN amount ELSE 0 END) AS spent,
       SUM(CASE WHEN type='CREDIT' THEN amount ELSE 0 END) AS income
FROM transactions
WHERE is_outlier = 0
GROUP BY month
ORDER BY month
```

> Drizzle exposes `sql` template tag for raw queries when needed.

## 11. Key Implementation Notes

**Setu sandbox testing:**
Use Setu's mock FIP (available in sandbox). It provides 15–30 transactions per account across 6 months. No real bank linking needed during dev.

**Tags as JSON array in SQLite:**
SQLite doesn't have a native array type. Store as JSON text (`text` column with `mode: 'json'` in Drizzle). Use `json_each()` in raw SQL for aggregation queries.

**"Unknown" tag state:**
Don't store a literal "unknown" tag. An empty `tags: []` array = untagged. The UI renders "Untagged" badge when array is empty. This avoids polluting analytics with a fake "unknown" category.

**Outlier exclusion:**
Every analytics query has `WHERE is_outlier = 0` — this is the single source of truth. No separate table, no soft-delete.

**Narration parsing:**
UPI narrations follow the pattern: `UPI/{refNo}/{receiver}/{sender_vpa}/{bank}`. Write a regex-based parser in `narrationParser.ts`. NEFT/IMPS have different formats — handle per-mode with a `switch` on transaction mode. Log unrecognized patterns.

**Deduplication:**
On each Setu fetch, use `INSERT OR IGNORE` (Drizzle: `.onConflictDoNothing()`) keyed on `setuTxnId`. Safe to re-fetch without duplicates.

**No auth required:**
This is local-only. The backend binds to `localhost:4000`. No JWT, no sessions. Keep it simple.
